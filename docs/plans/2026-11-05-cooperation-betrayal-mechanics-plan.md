## 1. 本次确认的玩法

**靠近选择 → 双方同意组队 → 连线与共享宝箱 → 拉开距离断线 → 中点爆箱 → 所有人争抢。**

用户已确认：

1. 靠近其他真人或 AI，可以选择“组队”或“忽略”。组队需要双方同意：一方发邀请，另一方接受后才成立；AI 按性格决定。
2. 选择忽略后，这两个角色之间 1 分钟内不能再次邀请或组队；双方仍可与其他角色组队。
3. 组队后产生连线。接近距离上限时连线变红预警，超过上限立即解散；共享宝箱在两人当时位置的中点爆开，掉落物公开争抢。
4. 取消“长按 F 踢箱背叛”。主动拉开距离是本次保留的主动背叛方式。

核心体验：合作时要保持距离；财富增加后，队友突然跑开便可能引爆共享利益。另一人可以选择追上、继续合作，也可以转身争抢。连线不是绳索，不拉拽、不强制减速、不阻止玩家离开。

## 3. 首版参数与状态规则

下面数值是执行建议初值，并非已经试玩调优。集中放在现有模拟模块的常量中，不增加配置文件或设置界面。

| 参数 | 初值 | 语义 |
| --- | --- | --- |
| `ALLY_INTERACT_DISTANCE` | 2.4 个逻辑单位 | 距离小于等于该值才可邀请/接受，沿用当前附近交互尺度 |
| `ALLY_INVITE_TTL` | 5 个局内秒 | 邀请超时失效；超时不是“忽略”，不自动产生 60 秒屏蔽 |
| `ALLY_IGNORE_SECONDS` | 60 个局内秒 | 只对无序角色对生效，例如 A/B 和 B/A 是同一条记录 |
| `TEAM_WARNING_DISTANCE` | 4.0 个逻辑单位 | 距离达到该值但未越过上限时，连线变红预警 |
| `TEAM_BREAK_DISTANCE` | 5.0 个逻辑单位 | 距离严格大于该值时立即解散；恰好等于上限不解散 |

距离使用模拟平面中角色脚底位置的欧氏距离，不使用屏幕像素、相机距离、路径长度或连线绘制长度。

计时使用对局已有的模拟时间。暂停时不流逝，开发加速按同一游戏时钟推进；UI 显示的是局内剩余时间。无需 `setTimeout`、系统时间、持久化存储或后台计时器；重开清空全部邀请与忽略记录。

### 最少新增状态

- 忽略表：`pairKey -> blockedUntil`；pairKey 按较小/较大 actorId 规范化。只有 10 名角色，不引入数据库或通用好友系统。
- 待处理邀请：`id / fromId / toId / expiresAt`。每名角色最多参与一条待处理邀请，不建立排队、优先级或邀请收件箱。
- AI 需要时增加一个简短的“打算拉开距离”意图，不能用该意图直接触发解散。
- 距离与预警状态从队友位置派生；不要在 UI 里再维护一份队伍权威状态。

已有 `nextEntityId` 等身份分配设施可复用。字段名称可随当前工程调整，上面描述的是语义，不要求照抄接口名。

## 4. 靠近、邀请与忽略

### 4.1 靠近时展示选择

候选角色必须同时满足：双方存活、彼此不是自己、均未组队、不在最终强制混战阶段、未被这对角色的忽略记录屏蔽，且在交互距离内。

有多个候选时先选最近的，等距按 actorId 决定，保持稳定。UI 明确显示名字/颜色及两个按钮：

- `与青岚组队`：发送邀请。
- `忽略青岚 60 秒`：建立这对角色的双向屏蔽。

面板不暂停游戏。目标一旦进入正在交互/邀请的状态，显示与事件绑定该 actorId，不能在用户点击时悄悄换成另一名最近角色。离开范围就收起当前附近提示；不自动替用户选择。

PC 可沿用 E 作为当前明确组队/接受按钮的快捷键；另为“忽略”配置一个未占用的快捷键，例如 X，并在界面说明。F 不再承担踢箱功能。触屏使用实际按钮，按钮上的对象和消息里的 targetId 必须一致。

### 4.2 邀请与接受

1. A 点击组队，只创建 A→B 的邀请。此时不建立连线、不创建共享箱、不授予合作加成。
2. B 收到 `A 邀请与你组队：[接受] [忽略 60 秒]`；A 显示等待状态，仍可正常移动和战斗。
3. B 接受时，模拟层重新校验距离、双方存活/空闲、屏蔽、邀请身份、有效期和对局阶段。校验通过后一次性完成双向关系与共享箱创建。
4. 成队后清除涉及两人的待处理邀请，避免第三人的旧接受消息再组出三人队。
5. 邀请期间任一方死亡、离开交互范围、加入其他队伍、进入最终阶段或对局结束，该邀请失效。没有主动点击忽略就不写 60 秒屏蔽。
6. 同方向重复发送不重复创建邀请，也不反复延长有效期。A→B 和 B→A 同时发生时，可以视作双方明确同意，原子地只建立一支队伍、一个箱子。
7. 一名角色正在处理另一条邀请时，返回简短的忙碌状态；不能静默覆盖其当前邀请或自动换目标。

真人↔AI、AI↔AI 使用同样的检查与成队入口。即使目前只支持一个本地玩家，也不能让 AI 的近距离扫描替玩家同意邀请。

### 4.3 忽略 60 秒

- 只允许对 UI 当前明确的角色或有效邀请执行忽略；忽略后清除这对角色的待处理邀请。
- 在 `now < blockedUntil` 期间，A/B 之间不能邀请、接受或自动成队。A/C、B/D 完全不受影响，攻击、冲撞与抢宝物也不受影响。
- 离开再靠近、AI 重试、重复的旧消息，都不能刷新或延长屏蔽。
- `now >= blockedUntil` 时重新获得资格；不会自动成队，也不自动重发原邀请。
- 忽略只在本局内存在，死亡不生成新的屏蔽，重开全部清空。
- 普通收起面板、走远、超时不等于忽略；避免玩家未操作就被锁一分钟。

本次**不增加背叛后的额外 60 秒禁组队**。原队友断线后若都愿意，可以重新靠近并再次双方确认；新箱从原有初始值开始，原先公共掉落物不会被自动回收。

## 5. 连线、中点宝箱与断线

### 5.1 连线呈现

- 从真实双向队伍关系读取双方脚底位置，每对只画一次，最多 5 条。
- 常态使用现有合作色；距离达到预警值时变红，HUD 提示“离太远会断线爆箱”。退回安全距离立即恢复，无额外倒计时。
- 连线贴近地面并略抬高，不能穿过头部遮住人物；遵循现有原生线段/网格资源管线，不新增覆盖 Canvas。
- 共享箱每步位于两人的实时中点。相机跟随、平滑显示、角色动画不能改变用于判定的真实坐标。
- 外部攻击打爆箱体之后，队伍关系与连线仍保留，距离检测仍继续。不能把 `chest.hp > 0` 当作“是否组队”的唯一判断。

### 5.2 统一距离判定

对仍存活、互为队友的角色对，在本步普通移动、冲撞及击退位移全部结算后，统一进行一次距离检测。不能仅在玩家移动函数或 AI 决策时检测，否则冲撞和另一方移动会漏判。

每对只处理一次，例如仅由较小 actorId 的成员发起本步检查。按下面顺序处理：

1. 本步进入最终强制混战，或队友已经淘汰：按已有对应流程清理，不再同时记作距离背叛。
2. 更新实际双方坐标与中点。
3. `distance <= TEAM_BREAK_DISTANCE`：保留关系，并派生正常/预警状态。
4. `distance > TEAM_BREAK_DISTANCE`：在同一步解散；清除双方关系和合作加成、移除连线；存在未破坏共享箱时，从当前中点爆开并释放全部箱内财物。

本步与后续攻击判定应看到一致的关系：距离断线后双方不再享有队友免伤。不要依次更新两个角色时得到“一方认为已解散，另一方仍是队友”的中间结果。

**爆箱原点必须重新计算：** `((a.x+b.x)/2, (a.y+b.y)/2)`，不能使用上一帧的箱体缓存位置、角色本人位置或屏幕中心。即使中点位于危险区域，也不擅自把掉落物搬回安全地块。

玩家被外敌击退导致超距也会断线，这是距离规则的自然结果；不另加免断线时间或保护罩。

### 5.3 爆箱与财物只结算一次

将两个操作区分清楚：

- **破坏箱体**：对仍有效箱体释放其剩余财物并销毁箱体，不自动解除组队。
- **解散队伍**：原子解除双方关系；原因是距离时，若仍有有效共享箱，再执行一次破坏箱体。

可以在现有模拟模块中使用两个小函数，不创建事件总线、通用事务框架或第二套队伍状态。

爆箱入口必须完成以下原子处理：取出原财物 N → 将箱体标为已破坏/无效 → 箱内财物清零 → 在给定中点生成总价值 N 的公共掉落物。重复调用不能再次发放 N。若用现有 `hp > 0` 作为存活条件，调用方不要提前把 hp 置零而绕过实际爆箱入口。

- 外部攻击已经打爆的箱子，之后距离断线只解散关系，不再掉第二份财物、增加第二次破箱计数或重复播放实体爆炸。
- 同一帧外部攻击与超距相遇，无论处理顺序如何，每箱最多释放一次原财物；距离超限的队伍仍必须解散。
- 空箱断线照常解散，可有破裂反馈，但不会凭空产生宝物。
- 已经散落的宝物始终是公共物，双方和第三人都能拾取；每件宝物最多发放一次价值。
- 个人已持有的宝物不因组队/断线被没收或复制；拾取后归个人的现有规则保持不变。
- 本次不新增箱体被外人打爆后的自动重建机制；沿用当前规则，关系可以处于“仍组队、已无箱体”的状态。

同一帧就被拾取的宝物不要求仍留在地上供测试数数组长度；通过爆箱时释放价值、剩余掉落与个人增量共同验证守恒。

涉及个人数值增量的守恒测试先安排未达现有宝物上限的角色，避免把原有上限截断混成爆箱重复/丢失。本次不修改个人宝物上限。

### 5.4 断线不自动判责任

仅凭距离无法可靠区分“谁主动背叛”：双方都可能在移动，也可能被外敌击退。首版不加责任归因算法。

建议把旧结算项“主动背叛次数”改成“断线解散次数”，只记录本地玩家参与的距离解散，每支队伍每次解散加一。AI↔AI 的断线不增加玩家个人次数；死亡、终局强制解散与外部单独爆箱不算距离解散。对应状态字段与读取方一起调整，不保留旧语义的隐蔽兼容分支。

世界提示可使用“连线断裂，队伍解散！”；不把两个玩家都强行标成主动背叛者。已有爆箱计数仅在实际有效箱体被破坏时按当前统计口径记一次，不因重复清理叠加。

## 6. AI 行为改动

沿用现有老实人、贪财鬼、掠夺者三类，不接入大模型，不新建复杂 AI 框架。

| 性格/状态 | 行为要求 |
| --- | --- |
| 老实人 | 倾向发邀请、接受有效邀请，成队后维持合作距离，避免为追一件远处宝物频繁意外断线 |
| 贪财鬼 | 可以接受合作；沿用已有财富阈值等策略产生背叛意图后，真实向远离队友的方向移动，而非直接调用解散 |
| 掠夺者 | 更倾向忽略邀请和攻击其他队伍，接受后也遵守相同连线规则 |
| 任意 AI 收到玩家邀请 | 在正常思考节拍决定接受/忽略；决定只做一次，不能逐帧掷骰子刷结果 |
| AI 邀请玩家 | 必须等待玩家接受，不能以 AI 的意愿代替玩家点击 |
| 普通合作 AI 追怪/捡物 | 候选目标会明显拉断线时，改选队友附近的合作目标；安全区与存活判断仍优先 |
| 决定背叛的 AI | 仍使用原有合法速度和移动规则；玩家追上后连线可以维持，不瞬移、不强制制造超距 |

距离检查每步执行，独立于 AI 约 0.5–1.2 秒一次的思考节拍。未处于背叛意图的 AI 不能因为原有“先追远处掉落物”的分支，组队几秒就普遍跑散。

识别自己的共享箱必须检查真实成员。当前 `actor.team` 是队友 id、`chest.team` 是建箱成员 id，不能简单使用 `chest.team !== actor.team` 判断敌方箱体，否则可能把自己的箱体当目标。只修正本次合作/掠夺涉及的判断，不顺带重构战斗系统。

接受/忽略概率若需调整，集中为少量常量；测试传入明确的 AI 选择或使用可控随机边界，不能反复执行直到“碰巧接受”。

## 7. 输入、消息与只读投影

继续使用现有 `island/controls` 及 `island.match`，不新建网络服务。

### 操作消息建议

在现有输入意图中增加针对目标/邀请的操作，含 `targetId` 或 `inviteId`，例如“发邀请、接受、忽略”。名称可依当前代码调整。

引擎模拟层始终二次校验。旧 UI 消息、重复点击、邀请过期后点击、目标已成队等情况均不能越权成队，也不能重新选择另一个目标执行操作。

当前本地前端只代表本地玩家，不能通过任意 `fromId` 代替 AI 或另一角色点击接受。AI 的响应只由模拟层决策生成。

移除 `kick` 消息、`kickHeld`、`kickCharge`、F 键绑定、踢箱按钮、蓄力进度、长按指针状态和旧提示文案。不要留下“新界面不显示，但旧消息仍能踢箱”的后门。

### 必要只读信息

按现有投影方式补充，不另建可写调试入口：

- 当前候选角色 id/名字、是否可邀请，以及明确的不可用原因。
- 当前发出/收到的邀请 id、双方 id、剩余时间。
- 相关角色对的忽略剩余时间；只向 UI 推送需要的部分，不必每帧传整张表。
- 玩家当前队友 id、实时距离、预警/断线阈值、自己的有效箱体状态与位置。
- 玩家最近一次距离解散的只读结果：递增序号、双方 id、原因、中点、实际释放价值。只需保留最后一条，不做全局录像系统；AI 之间事件不能覆盖玩家自己的验收结果。
- 玩家断线解散次数、已有个人宝物与箱体统计。

这些信息允许 UI 正确反馈、自动化验证自己的组队和爆箱，不允许外部直接改位置、强制组队、刷箱子或写胜利。

## 10. 必须覆盖的验收

### 纯模拟与 UI 边界

| 用例 | 通过标准 |
| --- | --- |
| 单方发邀请 | 双方仍是单人，无连线、无共享箱、无合作加成 |
| 接受邀请 | 双方互为队友，只创建一个箱子，清除相关待处理请求 |
| AI 邀请玩家 | 玩家未接受时绝不成队；AI↔AI 也不能绕过资格检查 |
| 双向同时邀请/重复消息 | 最多成队一次、建箱一次；重复操作不多发奖励 |
| 多人竞争同一角色 | 最多两人成队，其他旧邀请失效，不出现单向关系 |
| 忽略 A/B | A→B、B→A 都被屏蔽，A/C、B/D 可正常交互 |
| 60 秒边界 | 59.999 秒仍屏蔽，60 秒到期后允许重新邀请；离开/靠近/重试不刷新时长 |
| 邀请超时/走远/死亡/结局 | 请求失效，无自动成队，也无额外 60 秒处罚 |
| 精确距离边界 | 预警值变红；低于预警恢复；恰等于断线值保留，严格超过立即解除 |
| 谁移动都能断线 | 玩家、队友、双方移动和第三人击退引发超距都被统一检测 |
| 爆箱实时位置 | 先移动双方，再断线，原点等于本步中点，不是旧箱缓存位置 |
| 同一步重复检查 | 一对只解散一次；箱内 N 清零后最多释放价值 N，不双倍掉落或计数 |
| 外部攻击先爆箱 | 关系/连线保留；以后超距仍解散，但不再次发钱或重复爆炸 |
| 同帧外攻与超距 | 财物只释放一份，关系与距离规则保持一致 |
| 空箱/无有效箱的队伍 | 可正常断线，不凭空产生宝物；距离解散计数与实际爆箱计数区分 |
| 死亡/最终阶段清理 | 清除无效关系和邀请；不重复计为距离背叛，最终阶段不能重新组队 |
| 正常捡取公共物 | 双方与第三人都能抢，每件价值只结算一次；个人原财物不被没收 |
| 贪财 AI 背叛 | 存在真实跑开的移动过程；未超距不能直接解散，追上能继续保持关系 |
| 退役踢箱路径 | F、旧 kick 消息、旧长按 UI 均不能再触发爆箱 |
| 重开/失焦/卸载 | 屏蔽表与邀请清空，按钮/监听不叠加，不残留输入或旧连线 |

单元测试可以直接安排人物位置与箱内价值，隔离随机 AI/战斗后验证特定规则。这是测试夹具，不是给产品增加作弊入口。浏览器试玩则必须使用实际输入，不直接写模拟状态。

当前测试中用 `breakTeam()` 代替“外部掠夺”的用例，不足以证明外部爆箱保留关系；请改成覆盖真实攻击/破箱入口并显式断言双方关系仍在。
