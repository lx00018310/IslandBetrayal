## 1. 本次确认的产品设计（关键决策）

### 1.1 唯一战斗操作：四方向 + 一个组队键

| 场景 | PC | 手机 | 说明 |
| --- | --- | --- | --- |
| 战斗移动 | WASD / 方向键 | 左侧虚拟摇杆 | 支持对角移动，速度归一化。 |
| 组队/接受邀请 | **Space** | 唯一右侧【组队】按钮 | 靠近可邀请对象时请求组队；收到请求时接受。 |
| 普攻/三武器/技能 | **自动** | **自动** | 保留割草，不新增攻击、冲刺、投弹、技能、忽略按键。 |
| 背叛 | **拉开距离** | **拉开距离** | 保留 >5m 超距断线中点爆箱，不提供背叛按钮。 |
| 升级三选一/结算选择 | 左右方向切换高亮，**Space 确认** | 摇杆切换高亮，【组队】确认 | **菜单模态下**相同物理按键复用为“确认”，不会触发组队。 |
| 下一局/主菜单模式选择 | 方向键移动高亮，**Space 确认** | 摇杆 +【组队】 | 不新增常驻战斗按钮；可同时支持鼠标/触屏直接点击**非战斗菜单卡片**，但不能要求玩家依赖额外键位。 |

- 删掉正式 HUD 和正式键盘绑定中的 E、X、Q、R、1/2/3、冲撞键、忽略键、加速键、单独重开键。**开发调试工具可保留但必须明确隔离，不能出现在正式 UI/玩家输入映射。**
- 玩家未在邀请 5 秒内按 Space，即视为本次邀请到期，AI 不会因此卡住。是否施加 60 秒屏蔽：**保留明确 AI 拒绝的 60 秒屏蔽；玩家未回应仅使邀请自然过期，避免没有“忽略键”时产生不可解释的 60 秒锁定。**
- 附近有多名可组队对象时，Space 默认选择**最近且合法**的对象；靠移动切换近邻对象，靠头顶提示确认对象；不要添加目标切换键。
- Space 的功能由界面状态独占：`menu/upgrade/round-end/endless-pick` > `in-match`。单次输入只被一个上下文消费。对话/升级暂停期间模拟不推进。

### 1.2 普通模式 vs 无限模式

- **普通模式（保留）**：一局约 300 秒（最多延至 360 秒），结束后可再开始全新单局；所有属性、宝物和身份成长重置。
- **无限模式（新增）**：连续 1→2→…→N 局；仍然每局约 300 秒；**所有参赛角色**具有自己的无限进度与历史规则，不是只有人类玩家成长。
- 比赛要求 ≥15 分钟可玩体验：无限模式自然支持连续 3 局以上。**不能把菜单/暂停/死后观战时间计入有效体验。**
- 现阶段仍是 **1 真人 + 9 AI、本地单机**。不实现联网、账号或跨设备存档。身份在同一次无限挑战会话中稳定：`actor.id`（0～9）。未来联网时才能用真正的 player ID 替换，**现阶段不做在线身份系统**。
- 不同角色拥有自己的 `endlessRound`/成长历史，不能因为全局 `roundIndex` 为 N 就把所有新角色当成 N 级角色。当前固定 10 人连续参赛，全部角色都持续积累；未来如果某角色不在下局，则其规则不进入本局计算，重新出现才恢复其历史。

### 1.3 每人秘密决定下一局的**全场规则**

> 对“使下一局的某个属性**所有人**增减 10% 或 20%”的明确实施解释：**每一名角色在局末选择一个全局修正；该修正影响下一局场上所有角色（包括选择者），并在该角色持续参赛的后续各局保持生效。** 不仅是给自己加成，也不只随机抽出一个全场规则。

- 每局结算后，各角色（存活与被淘汰者）都能贡献 **1 条**规则，避免早死角色永久无法成长。
- 规则格式：`{ ownerId, stat, factor, chosenAtRound }`。
- 可选目标：**最大血量、伤害、移动速度、攻击速度、暴击概率**（先只做 5 个数值）。
- 可选修正：**+10% (×1.10)、+20% (×1.20)、-10% (×0.90)、-20% (×0.80)**。
- **相同属性的不同规则按乘法累乘，不按加法互相抵消。**
- 比如 A 第 1 局选“全员血量 +20%”，B 选“全员血量 -10%”，第 2 局全体最大血量乘数 `1.20 × 0.90 = 1.08`；第 2 局 A 又选 +10%，第 3 局为 `1.20 × 0.90 × 1.10 = 1.188`（两人都持续参赛时）。
- 每名角色的规则归属其 `EndlessProfile`，若某人没进入下一局，该角色所有历史规则**暂不参与本局**，以后再次出现再参与；**不会删除历史**。
- 全部玩家规则在本局结束后**独立且保密**选择；AI 按性格与简单权重选择；人类在局末菜单选择。
- **本局结束前不预先显示别人的选择；下一局开始时公布“最终全场修正”总览（可选择显示规则来源），避免玩家不知道为什么突然变化。**
- 进入下一局时，把当前所有参赛者的历史规则一并计算一次；本局期间不再动态改变此类世界乘区。
- **重要平衡约束：** 10 人 × N 局会快速指数增长。保留完整原始因子历史（满足累乘机制），但**应用到角色时启用安全上下限**；达到上/下限的选择应在 UI 显示“已达有效上限”，并避免强制玩家选择无效属性。参数见第 3 节。

### 1.4 每人最多带一件“宝物（含等级）”进下一局

**基线限制：** 现有 `treasure` 只是“金色财物点数”，没有可持有、可升级的独立宝物库存；已有可以升级的具体物品是 `weaponKnife / weaponArrow / weaponBomb`。

因此**最小实现**：
- 首版把**三种已实现的武器**视为可携带的“战斗宝物”：**环绕飞刀、穿透箭、范围爆轰**。玩家选其中**一件已拥有的宝物**（含当前武器等级 1～3）带到下一局。
- 数据形如 `carryRelic: { kind: 'knife' | 'arrow' | 'bomb', level: 1 | 2 | 3 } | null`。**升级等级完整继承**；物品没有被拿到就不能虚构为可携带。没有武器则自动选 `null`。
- `ActorState.treasure` 的金块数量、共享宝箱财物、XP、其他两件武器、普通卡牌当局属性**不继承**，避免当前财富规则被偷换成局外永久成长。
- 下一局开始时，带入武器等级；其当前局继续可以按原有升级规则成长至 3 级，下一局再次只能带一件。
- AI 也依相同规则选一件（例如贪财偏高等级、掠夺者偏攻击类），不能全武器带走。
- 若以后要引入全新的“可升级遗物”品类，**先让这三件跑通再单独立项**；本次禁止另建复杂背包、装备合成系统。

## 2. 无限模式运行状态与跨局生命周期

**只在原 `island.pack.ts` 插件生命周期中维护一个会话对象**，不要引入新服务器、数据库或平行 ECS 状态机：

```ts
// 示意类型，字段名以实际代码风格调整
interface GlobalRule {
  ownerId: number;
  stat: 'maxHp' | 'damage' | 'moveSpeed' | 'attackSpeed' | 'critChance';
  factor: 0.8 | 0.9 | 1.1 | 1.2;
  chosenAtRound: number;
}
interface CarryRelic {
  kind: 'knife' | 'arrow' | 'bomb';
  level: 1 | 2 | 3;
}
interface EndlessProfile {
  actorId: number;
  endlessRound: number;   // 该角色参与到第 N 局，不由全局索引假定
  rules: GlobalRule[];
  carryRelic: CarryRelic | null;
}
interface EndlessRun {
  mode: 'normal' | 'endless';
  matchIndex: number;
  completedRounds: number;
  activeElapsedSeconds: number;
  profiles: Map<number, EndlessProfile>;
  phase: 'playing' | 'upgrade' | 'round-result' | 'endless-choice';
}
```

### 单局结束 → 下一局（必须原子执行）

1. 原有 `gameOver/winner` 先结算且冻结战斗，**仅一次**触发 `finishRound()`；所有 10 名角色都有个人的下一局选择资格。
2. 普通模式：只显示结算/下一局，使用 `Space` 确认直接完全重开，不保留 Rule/Relic。
3. 无限模式：显示结果，然后对真人依次展示 **A. 下一局全场属性规则（选属性和 ±10/20%）**、**B. 本局携带宝物（选自己拥有的 1 件）**。用方向键/摇杆移动高亮，Space/组队按钮确认；UI 不增加常驻动作键。
4. AI 根据自己的个人 profile/当前物品选择规则和宝物（隐藏选择）；选择过程只运行一次，避免重开重复叠加。
5. 全部选定后执行 `startNextRound()`：本局保存的 10 人各 1 条规则追加进对应历史；为下一局参赛者聚合所有历史规则乘数；调用已有 `restartSimulation()` 清理单局；再按角色 ID 应用世界乘数和携带武器等级；重置镜头、地块、弹幕、HUD；`matchIndex++`。
6. **跨局数据只有 `EndlessRun.profiles` 和累计体验时间等会话字段**；`sim.actors[]` 是每局新建的运行态，不能把完整旧 ActorState 直接拷贝到新局（会带入死亡、残血、队伍邀请、CD、伤害标记等残留）。
7. 如果真人点击“全新无限挑战”，重置全部 profiles、规则、宝物和局数；菜单使用同一 Space 确认流程。刷新页面默认结束当前会话，不实现持久存档。
8. 某一角色未参加本局时，其个人历史不清空，但对当前世界计算不生效；未来加入真人联机时再设计实际身份匹配策略。
9. **防止套娃翻倍**：每局只在重置后的基础值上应用一次由历史规则聚合的乘数，禁止在上一局已修改的最终值上继续乘；历史由规则列表保存，最终值每局重算。

## 3. 统一数值系统（借鉴 PoE 的计算分层，不实现 PoE 全量复杂度）

### 3.1 唯一计算顺序

**P1 增加一个很小的纯函数模块**（推荐 `assets/island/stats.ts`）；其它业务代码只读取它的结果：

```text
最终属性 = 限幅并按属性取整(
  (基础值 + 固定加减值之和)
  × (1 + 本局同类百分比加减值之和)
  × ∏(所有当前参赛者历史全场乘数)
  × ∏(该属性明确允许的独立状态乘数)
)
```

- **固定加减**：基础普攻 + 财物加成、结盟加成、箱子加成等既有规则；**不重复叠加**。
- **加法百分比区（Increased/Reduced）**：本局升级卡：伤害 +15%、速度 +8%、攻速 +10%、范围 +15% 等；同类直接相加，先封低于 -90% 的极端值。
- **独立乘区（More/Less）**：无限模式每个历史全场修正规则独立 `×1.1/1.2/0.9/0.8`；叠加先后**不受角色选取顺序影响**。
- **最后**才应用明确的生命、速度、攻速、暴击上下限、伤害取整；显示层使用实际有效值，禁止用未经限幅的乘数展示假收益。
- **战斗临时状态**（如拾取减速 ×0.55）在主移动速度计算完成后单独施加；与无限模式永久规则区分，不能写回基础值。
- 源代码**只能有一套数值权威接口**，例如 `getEffectiveStats(actor, matchRules, context)` / `getHitDamage()`，`ActorState` 旧字段可逐步作为本局加法加成存储，禁止所有调用处各自再乘一次全场系数。

### 3.2 初始参数与安全边界（为无限 N 稳定可玩）

| 属性 | 基础值/约定 | 全场规则作用 | 最终有效范围（首轮建议） |
| --- | --- | --- | --- |
| 最大血量 | 100 | 相对倍率乘法 | 50～300 HP |
| 攻击伤害 | 沿用现有基础普攻 10 + 财物/队伍加成 | 相对倍率乘法 | 0.5～4 倍于对应基础伤害；最终最少 1 |
| 移动速度 | 原版 3.1 | 相对倍率乘法 | 0.6～1.8 倍基础速度（碰撞与视觉安全） |
| 攻击速度 | 对实际攻击**频率**应用倍率；CD 按频率倒数换算 | 相对倍率乘法 | 0.5～2.5 倍基础频率；CD 保留底线 |
| 暴击率 | 建议基础 5%（如果当前完全没有则新增） | **相对变化**；例如 +20% 将 5% 变成 6%，**不是 +20 个百分点** | 0～60%；默认暴击伤害 ×1.5 |
| 武器等级 | 0～3 | 不属于世界属性倍率；一件可携带 | 严守原最高 3 级 |
| 技能范围 | 目前存在 `statAreaBonus` | 暂由本局升级决定，不纳入首版跨局世界规则池 | 根据战斗地图设置上限 |

- **倍率仍按真实乘积累积并存档于本次 EndlessRun 的规则历史；有效战斗值限幅。** 避免无限第几十局速度过快、CD 过短、概率超 100% 或数值 NaN/Infinity。
- 在 UI 中标明 `原始全场修正 + 实际生效修正`；若某属性已达到有效上限，局末选择时可提示并禁止无收益选择，提供其他合法属性。
- 暴击使用**单次命中**判定；同一枚飞刀对同目标未满足命中冷却不能多次掷暴击；需要可复现的测试 RNG（传入随机函数或 seed）。
- **先不添加高级“局外数值词缀”“乘法标签树”“特殊技能树”**。保持本局加法区、无限模式世界乘区、携带武器等级三个清晰来源。

### 3.3 算例（必须写入测试）

假设基础血量 100，固定加值 +20，本局卡牌 +15%，A 的全场历史选择 +20%，B 的全场历史选择 -10%：

`MaxHP = round((100 + 20) × (1 + 0.15) × 1.20 × 0.90) = 149`

若后续 A 再选择血量 +10%，第三局同场：

`MaxHP = round(120 × 1.15 × 1.20 × 0.90 × 1.10) = 164`

此处原始倍率不会写回基础血量。B 缺席时，B 的 ×0.90 暂时不参与当前局计算。

## 6. 强制测试清单（关键边界）

1. **操作：** 实战只有方向和 Space/组队按钮；没有其它必需键；升级/结算/规则选择占用 Space 时不触发战斗组队。
2. **战斗：** 飞刀同一目标 0.35–0.5s 命中 CD；三武器与普攻都遵守“队友免伤、外敌先攻击共享箱、外部破箱不散队、财物只散落一次”。
3. **计算：** `1.2×0.9=1.08`；`1.2×0.9×1.1=1.188`；公式与操作顺序无关，重复结算不翻倍，非有限数不进入战斗。
4. **生命：** 跨局 HP 恢复到本局**新最大 HP**，不沿用旧局残血或旧局旧最大值。
5. **速度/攻速/暴击：** 负倍率不能变成负移速、零 CD、超过 100% 暴击；达到安全界限有清晰反馈。
6. **身份：** A 的历史不落到 B 身上；A 缺席时不影响所有人，A 返回恢复贡献；首次出现角色无过往历史。
7. **秘密规则：** 局末每人各选 1 条，AI 完全参与；未进入下一局前不公示其他角色决策；不得因多次确认追加同一条两次。
8. **宝物：** 仅一件物品完整带级；零装备可选 `null`；无共享财物、个人金块、XP/其它武器跨局。
9. **重开：** 普通模式与全新无限挑战可彻底清空；继续无限挑战只保留预期 history / relic，不保留单局临时状态。
10. **赛事：** 900 秒有效**本人存活战斗时间**计算正确；死亡、选择界面、结束界面、调试加速不计；玩法可连贯游玩 15 分钟以上。
11. **真实试玩：** `playthrough.mjs` 关键步骤不能有 `.catch(() => {})` 后虚报成功；每个关键玩法实际触发一次，写入投影断言和对应 PNG。
12. **性能：** 10 人 × 40 怪 × 3 武器下不会因规则历史长度逐帧重算而卡顿；世界乘数**每局初始化时缓存一次**，不是每次攻击遍历 N 局历史。
