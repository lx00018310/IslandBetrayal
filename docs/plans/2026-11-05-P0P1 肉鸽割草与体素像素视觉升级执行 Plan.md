### 0.2 15 分钟要求的最小实现（由待定改为必做）

- **单局仍约 5 分钟。** 复用现有“结算 → 再来一局”机制，新加**「连续挑战」**流程。默认引导体验 3 局，并**允许继续挑战**，直到累计有效游玩时间达到 **≥900 秒**；若单局提前淘汰或提前结束，可立即开始下一局，不要求观众干等，也不限制继续玩。
- 仅增加本次游戏会话的 `challengeElapsed`（累计有效模拟运行时间）与 `roundsCompleted`（局数），以及界面上的 `挑战进度 / 当前局数`。**每局 XP、技能、队伍、财物继续重置，不做跨局养成。**
- `challengeElapsed` 不计升级暂停、结算屏等待、失焦停顿或其它非互动时间；不可通过 4 倍调试加速“刷出”15 分钟验收。允许普通单局模式，但**默认推荐连续挑战入口**，让评委真实体验足够长的流程。

## 1. 目标、核心循环及明确边界

### 1.1 目标体验

**10 名角色在像素体素荒岛上割草杀怪 → 获取经验与个人成长 → 结盟共享宝箱攒财 → 背叛/外部破箱/宝物哄抢 → 缩圈决出幸存者。**

设计定位：
- 观感参考 tibo.dog 的**近景俯视、清晰像素轮廓、密集自动攻击与掉落反馈**；
- 独特差异是**双方确认结盟、共享宝箱、超距断线、敌队破箱、公共战利品争夺**；
- 一局约 5 分钟，初期仍为 **1 位本地玩家 + 9 位 AI**；本 Plan **不实现真人联机**；
- 同一规则作用于玩家与 AI；AI 不通过特殊豁免获得战斗优势。

### 1.2 P0 与 P1 范围

| 级别 | 功能 | 可验收产物 |
| --- | --- | --- |
| P0 | 正交体素像素风视觉统一 | 角色/场景/宝箱/怪物统一风格，镜头与遮挡稳定 |
| P0 | 基础战斗特效与精简 HUD | 攻击、受击、击杀、掉落、拾取、结盟、断线、爆箱清楚可辨 |
| P0 | 割草怪潮 | 怪物从 6 只升级为受控波次，随时间明显增多 |
| P0 | 经验与随机升级三选一 | 玩家可升级；AI 自动选择；升级不破坏结盟规则 |
| P0 | 3 类额外武器 | 环绕飞刀、穿透箭、范围爆炸 |
| P0 | 宝物双重成长 | 个人宝物与团队共享宝箱职责清晰、收益可见 |
| **P0（赛事必需）** | **累计 15 分钟连续挑战** | 单局约 5 分钟、可连续多局，实际有效游玩时间 ≥900 秒 |
| P1 | 1 类 Boss | 登场预警、攻击、血条、击败奖励 |
| P1 | 基础技能组合 | 武器升级 + 攻速/范围/伤害等通用强化 |
| P1 | 2 类事件 | 宝物雨、怪物暴走；明确提示与结算 |
| P1 | 美术、交互、音效打磨 | 统一像素风、可读性、反馈、双端布局 |
| P1 | 终局胜者判定修正 | 不再在 300 秒仍多人存活时直接选数组首位 |

**不做：** 真人人机混合联网、账号系统、赛季/跨局养成、商城/货币/付费、背包合成、宠物、地图生成、多角色职业、多地图、新增通用状态机/ECS 框架、物理引擎重写。**连续挑战只累计本次会话时间与局数，不属于局外养成。**

### 1.3 必须保留的既有规则

- 最多两人一队；**发送邀请后对方同意**才能组队；忽略后双方 **60 秒**不得组队。
- 结盟连线，距离达到 4.0 预警，**严格超过 5.0** 才断线；断线时共享宝箱于**两人中点**爆炸。
- **外部攻击打爆宝箱不自动解散原队伍**，掉落公开争抢。
- 怪物掉宝、个人拾取宝物、冲撞、队友免伤、边缘坠落淘汰、缩圈、结算和重开均保留。
- 保留既有金币/宝物计数及伤害上限含义；扩展之前先写清“现有数值”与“新增数值”的边界。
- 不能复活已淘汰角色；必须正确清理队伍关系和对应状态。

## 2. 视觉规格：体素本体、像素观感

### 2.1 风格与镜头

- **风格：** Q 版、低饱和自然色地表 + 高对比玩家/怪物 + 金色战利品 + 红色危险区；全程保持“体素几何”可识别。
- **镜头：** 保留原生正交相机，约 55° 斜俯视、玩家局部跟随、平滑插值；角色在 1280×720 的屏幕轮廓建议约 70–100px 高，按实机调整。
- **地面：** 连续草地视觉；可薄层体素地块崩塌，避免满屏明显方格纹；保留可辨悬崖、沙滩、海/虚空。
- **光照：** 单一主光方向 + 柔和环境光；统一脚底阴影和遮挡，避免像素材质模糊。
- **重要：** 摄像机只改呈现，不改 `simulation.ts` 世界坐标、技能射程与拾取半径。
- **当前已有基础：** `assets/island/art.pack.ts` 的体素角色/薄层地面、`presentation.ts` 的正交镜头/影子/受击红闪。**增量精修而非重做。**

### 2.2 素材规格与最小资产清单

优先 **程序化体素几何/原生 Pack 管理的原创低分辨率材质**，不得以未经证明的“像素贴片必定符合参赛要求”为前提。

| 类别 | 最小素材 | 制作方式 |
| --- | --- | --- |
| 玩家 | 1 套共用 Q 版比例 + 10 种服装/头饰差异 | 在现有几何体素角色上做差异，先不做 10 套动画 |
| 普通怪 | 3 种视觉类别：小型追逐怪、笨重怪、迅捷怪 | 共用基础几何，调整体积/颜色/角/眼/移动节奏 |
| Boss | 1 种明显大于普通怪的体素 Boss | 重用怪物结构扩成独立轮廓，带明显弱点/危险提示 |
| 共享宝箱 | 3 个财富档：普通/富有/豪华 | 共用实体，换材质、体积、镶边、微量光效 |
| 宝物 | 金色小体素、经验晶体（建议青绿） | **经验与可抢夺宝物必须不同色** |
| 武器特效 | 飞刀、箭矢、爆炸圈 | 简单体素网格 + 程序移动/旋转/缩放 |
| 环境 | 草地/沙滩/岩石/灌木/悬崖 | 基于原始场景变体，尽量复用资产 |

色板建议（初始值，非硬性比赛要求）：
- 草地 `#647544`，暗草 `#4D6039`，沙岸 `#C5AB78`；
- 怪物紫灰/深红；宝物金 `#F3C65B`；经验青绿 `#65D5B0`；
- 连线正常青蓝、断线预警红 `#D9534F`；HUD 使用深色半透明底。
- 使用一致的低分辨率纹理采样；不要以全屏模糊、泛光掩盖素材缺陷。

### 2.3 动画与视觉反馈（按重要性排序）

**P0 必做：**
- 普攻/飞刀/箭矢/爆炸命中：短闪、伤害数字或清晰命中反馈（同类效果可合并）。
- 怪物死亡：体素碎裂/缩小消失、经验与宝物明显弹出。
- 拾取经验：青绿微粒飞向角色/经验条；拾取宝物：金色微粒与数值变化。
- 共享宝箱：体积/装饰随财富阶段变化；受击短暂红闪/震动；破箱 **200–350ms** 金色粒子飞散并弹落。
- 结盟：线条点亮；距 4.0m 变红；断线：瞬时断裂+中点爆箱。
- 受伤闪红、冲刺残影、缩圈边缘可视预警。

**P1 打磨：**
- Boss 地面警戒圈 + 出场提示 + 顶部血条。
- 小幅镜头抖动只用于爆箱/Boss 重击，支持减弱强度，不能影响移动操作。
- 统一打击音、升级音、爆箱音、拾取音、危险音；先可用原创占位音，默认合理音量。
- 不做高成本骨骼动画、复杂实时物理散裂和全屏后期特效。

**性能边界：** 粒子对象池/数量上限，视觉体素碎块数量与实际 loot 数量解耦；高负载时减少非关键视觉，不删真实游戏掉落。

## 3. 交互 / HUD

### 3.1 布局

- **顶部常驻：** LV/经验条、剩余时间、存活人数、个人宝物、HP（空间不足时收起次要项）；连续挑战模式额外显示简洁的**累计可玩时间/局数**。
- **游戏中央：** 保持无遮挡；临近队伍/宝箱时显示局部财富与耐久；结盟状态用连接线传达。
- **PC：** WASD/方向键移动、Space 冲撞、E 邀请/接受、X 忽略；自动攻击不新增攻击按键。
- **移动端：** 左摇杆 + 右侧【结盟】【冲撞】；多指独立处理 pointerId，松手/失焦清零输入。
- **升级：** 三张卡片（武器图标、名称、效果、等级），PC 按 1/2/3 或鼠标点选，手机点击；显示当前卡片的增益数值。
- **结算：** 生存名次、获胜者、杀怪、击败玩家、宝物、爆箱、断线数、重新开始。复用现有结算 UI。

### 3.2 单机暂停与多人兼容边界

- **当前是单机 1 人 + 9 AI：** 玩家升级时仅暂停本局**整个模拟时间**，所有角色、攻击、怪物、缩圈和倒计时同时停；UI 不停，以便选卡。
- AI 升级自动选卡，不触发暂停或 UI。
- 选择卡片由 `island/controls` 现有消息通道传递 `upgrade` + 被选择的 `choiceIndex`；由模拟层校验是否合法。
- **禁止**引入 WebSocket、第二个游戏循环或前端自己修改战斗属性。
- 将来真人联机的“不暂停全场”留待联机阶段，现阶段不实现。

## 4. 玩法规格（P0）

### P0-A：怪潮与割草

**现状：** `simulation.ts` 固定创建 6 只怪物，`presentation.ts` 固定遍历 6 个展示位置。需要同步扩展。

最小设计：
- 3 种普通怪物共用 `MonsterState`，加入 `kind / maxHp / damage` 等必需字段；视觉与数值按 `kind` 区分。
- 保持**受控数量**，建议同时存在怪物上限从 **24 起步，逐步调到 40**；Boss 额外单独计数。不要首版追求 100–500 只。
- 0–60s 少量、60–150s 中量、150–240s 高密度、240s 后终局高压；刷新间隔逐步缩短。
- 新怪物须生成于**当前存活地块**、离玩家足够远但在战斗区域可达处，不可生成在海里/塌陷区域/人物身体内。
- 保持现有 AI 攻击和合作关系；怪物应有基础追逐/靠近攻击，不只是站着等玩家自动打。
- 用复用怪物数据/实体池，隐藏死亡怪物并等待复用，避免不断建/销引擎实体。
- **验收：** 各阶段可见怪潮增强；玩家能连续杀怪；怪物不会持续卡死在崖外或出生时即重叠。

### P0-B：经验和随机升级

**经验 XP 与宝物 Treasure 分开：** XP 只用于当局升级，Treasure 仍参与原有“团队宝箱/个人战力/爆箱争抢”。

最小字段（仅示意，不要求照抄类型名）：
- `ActorState`: `level, xp, xpNext, upgrades/weaponLevels`；
- `SimulationState`: 本地玩家待选择的 3 个升级项（或最少一个 `pendingUpgrade`）；
- 单局重开完全重置以上字段。

默认起步数值（全部可配置）：
- 普通怪死亡给予击杀者 XP +1；Boss XP +8；
- 一级起始，升级阈值可按 `3 + level*2`，前期升级快，后期变慢；
- 每次从合法升级池中抽 3 个不重复候选；全部满级时自动替代为通用加成，不出现空卡；
- AI 采用简单权重随机选择技能，不能使用不存在的升级项；
- 升级面板必须在模拟正确暂停后出现；选中且校验通过才继续。

**边界：** 怪物掉落的宝物机制不删；经验由击杀即时获得或青绿晶体自动归属任选**一种**实现，避免同时做两套重复结算。建议首版采用**即时 XP + 青绿飞行动画**，省去额外物理拾取系统。

### P0-C：三类武器

首版保留现有自动攻击作基础攻击，只**附加** 3 种通用武器。三者与玩家、AI 使用同一套计算：

| 武器 | 行为 | 最小实现 |
| --- | --- | --- |
| 环绕飞刀 | 围绕主人旋转，触碰怪物/敌方造成伤害 | 3D 几何实体围绕玩家按角度计算；每目标命中冷却 |
| 穿透箭 | 朝最近有效目标发射，穿透多个敌人 | 自己维护 `pos/dir/lifetime/hitIds`；线段或小范围碰撞 |
| 范围爆炸 | 周期性对周围区域伤害 | 定时检测圆形半径 + 一次性爆炸圈 |

约束：
- 武器等级 1–3；先不做几十种组合、不做武器合成树。
- 武器可攻击怪物和敌方角色，但**遵守原队友免伤**；敌方宝箱承担伤害时继续沿用既有保护/破箱逻辑。
- 新攻击**统一调用伤害结算入口**，避免飞刀绕过宝箱直接秒杀角色，或多次掉落/击杀重复结算。
- 不以实际渲染帧率决定伤害；投射物、旋转与命中使用 `dt`，并有命中次数/对象上限。
- 按模拟数据驱动视觉，无第二份“表现层独立击杀”。

### P0-D：宝物与升级的关系

- 怪物掉落原有财物：**结盟杀怪进团队箱；非结盟归个人**；散落财物任何人可拾取。
- 个人 Treasure 继续提高攻击伤害（保留原有上限），共享宝箱继续带来队伍加成；不得把 XP 存进共享宝箱。
- 击杀、宝物哄抢、合作累计与武器成长的数值分开计算，并在 HUD 中明确展示。
- 防止宝物越多攻击越强导致正反馈失控：先保留 `calculateAttackDamage()` 封顶规则，武器单独有限等级。
- **可玩性验收：** 合作更容易积累宝箱；背叛能夺取财富，但会失去合作加成和保护；高等级个体不能一瞬间无代价吞掉所有宝物。


### P0-E：赛事规定的 15 分钟可玩体验

- 保留单局 300 秒的核心竞技节奏，不修改现有 P0/P1 所有事件的局内时间线。
- 在现有结算/重开流程上加入 **「连续挑战」**入口：连续运行多局，保留本次会话累计有效时长与局数，单局初始化仍独立重置全部战斗状态。
- 玩家提前淘汰即可选择**立即下一局**，完整 3 局不一定有 900 秒，因此不足时继续挑战。时间统计只计实际有效游玩时间。
- 连续挑战模式的本局结束不得误清空累计时间；完全退出挑战后重新开始则清零。无需持久化账号、数据库和跨局奖励。
- 可选显示会话总计（累计宝物/总击杀）仅在已有数据易复用时加入，**非必需**。
- **验收：** 正常玩家操作可连续体验至少 900 秒有效玩法；测试包含提前死亡、提前获胜、暂停选卡、结算停留和继续重开，累计时间与局数不重复、不跳增。

## 5. 玩法规格（P1）

### P1-A：Boss

- 一局先只出现 **1 名 Boss**，建议在 **180 秒**出场。
- Boss 使用独立 `kind`、更高 HP、易辨认体型、追逐/范围攻击与短暂前摇预警。
- 出场屏幕提示 + 地面警告圈 + Boss 血条，不需要复杂剧情/镜头过场。
- 击败奖励 XP +8 与一批公开宝物（实际数量配置化）；公开掉落可诱发多人哄抢。
- Boss 按阵营判断目标，不能无视结盟/免伤规则；出场或死亡不破坏缩圈流程。
- 验收：提前警告、能够击败、奖励只结算一次、同时存在怪潮不闪烁/掉帧严重。

### P1-B：轻量技能组合

不再做一个新技能系统；**扩充 P0 升级池**：
- 可选升级示例：攻击速度 +10%、伤害 +10%、技能范围 +10%、移动速度 +5%；
- 武器到 3 级后不再出该武器升级；无合法武器时仍有通用属性选项；
- 属性上限需配置，避免无限叠加；
- UI 每张卡片显示“当前 → 选择后”的真实效果；
- AI 与真人使用相同的加成公式。

### P1-C：两种特殊事件

基于 `sim.elapsed` 触发，不做通用事件编排框架：
1. **宝物雨**：在安全区域释放少量公开宝物（例如 6–10 个），触发争抢；避免贴着崖边产生无法拾取的财物。
2. **怪物暴走**：短时间提高刷怪/速度（例如 15 秒），屏幕有明显提示，结束自动恢复。

每局可按固定时间段选择执行，如 90s 和 220s；事件有触发标记，不能重复触发；重开要重置。

### P1-D：终局与结算正确性

发现的现有问题：`checkGameOver` 在 `elapsed >= MATCH_SECONDS` 且**多人仍存活**时，将存活数组的第一个角色当作胜者，这不是“最后幸存者”。

最低限度修复：
- 常规 300 秒结束时进入**决胜加时**；禁止新结盟，加速危险区收缩，让 AI 互相追击；
- 当唯一一人生存才宣告最后幸存者；
- 必须设**安全兜底**：若加时达到约 60 秒仍多人存活，则依**明确、可见且稳定的平分规则**结算（例如 HP → 淘汰数 → 宝物数 → ID），并在画面写明“加时积分决胜”，不要假装是唯一存活者；
- 玩家死亡也应能正常看到名次与胜者，游戏结束后模拟冻结，重开复原。
